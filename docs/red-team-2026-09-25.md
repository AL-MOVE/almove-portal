# Red team — AL MOVE Development

**Data:** 25-09-2026  
**Âmbito:** Portal do Cliente, App Coach e CRM em Firebase Development. A Produção não foi alterada.

## Métodos aplicados

- Revisão estática das rotas API, regras Firestore, autenticação, autorização, CSP, PWA e saídas HTML dinâmicas.
- Validação automatizada dos contratos, migração, paridade, sintaxe dos scripts Coach e encoding de conteúdo dinâmico.
- Auditoria de dependências (`npm audit --omit=dev`): sem vulnerabilidades conhecidas.
- Teste externo anónimo ao preview: corretamente bloqueado pelo SSO da Vercel. Não foi tentado qualquer contorno dessa proteção.

## Resultado

| Prioridade | Achado | Estado |
| --- | --- | --- |
| Alta | Valores provenientes de dados de clientes podiam ser inseridos no HTML da App Coach sem encoding em alguns cartões e editores. | Corrigido: todos os contextos identificados usam encoding HTML e os argumentos de handlers inline são escapados. |
| Média | A CSP permite `unsafe-inline` em scripts e estilos, necessário pela estrutura atual de HTML com scripts e handlers inline. | Aberto: migrar scripts para ficheiros externos e usar nonces ou hashes antes de remover esta exceção. |
| Média | Os papéis `coach` e `admin` têm acesso operacional amplo aos clientes Development; não há limitação por carteira atribuída. | Decisão de produto: implementar `assignedCoachId` se cada coach só puder consultar os seus clientes. |
| Média | A API ainda mantém o cabeçalho legado `X-ALMOVE-Session` quando não recebe Bearer Firebase, por compatibilidade com Apps Script. | Aberto: definir data de fim e exigir Bearer Firebase em todos os pedidos. |
| Baixa | Não existe limitação de taxa explícita nas rotas Vercel para pedidos autenticados. | Aberto: adicionar rate limiting e alertas de abusos quando a solução de infraestrutura estiver definida. |
| Informação | O preview Development exige SSO Vercel para utilizadores anónimos. | Confirmado: é uma barreira adicional adequada; os testes completos de fluxo devem usar contas de teste autenticadas. |

## Controlos confirmados

- Firestore recusa leituras e escritas diretas do browser por defeito.
- Rotas CRM validam token Firebase revogado, email verificado e papel de equipa; a migração exige `admin`.
- Cookies CRM são `HttpOnly`, `Secure` e `SameSite=Lax`.
- A API evita encaminhar o token Firebase bruto ao Apps Script; usa uma asserção curta assinada pelo servidor.
- PWA, manifestos e service workers do Portal e Coach estão separados para não partilharem cache nem rotas.

## Próxima prioridade

Planear a remoção progressiva de JavaScript inline. É a melhoria que mais reduz o impacto de qualquer regressão futura de XSS, sem afetar o desenho nem os fluxos atuais.
